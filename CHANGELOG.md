## 0.12.0 - 2026-10-20

Commit `631de5fe0346`; release record `pub:sha2-256:dkcoksvfcez4lesiglmnf2b6h5c2h5ozsoc7no2ugrrex7ty27ta`.

### Changed
- pubkit protect no longer ships a list of repositories: it reads protected.json in the working directory, or --config FILE, or protects the repositories named with --require CHECK (repeated) and no list. pubkit's own list is protected.json at its root. pubkit new prints the pubkit protect --require line for the new package

### Fixed
- pubkit protect prints the reasons GitHub gives for rejecting a ruleset, such as a required check's app not being installed on the repository, and says a repository admin must run it only when GitHub refuses access (HTTP 403 or 404)

## 0.11.3 - 2026-10-20

Commit `b641583f31a8`; release record `pub:sha2-256:us6norq6xnxso7yawhr55vwgfpmbsi4lsu2gtsqgzjil3gktpjea`.

### Added
- python-ci's sonar job reads the coverage report the functional job's test command writes (coverage-report, by default coverage/coverage.xml), so SonarQube Cloud's quality gate can measure coverage on new code; pubkit's own suite now measures itself, the pubkit processes it starts included
- rust-ci measures coverage when it has a SONAR_TOKEN: pubkit.mk's new coverage target runs the Rust tests and the Gherkin suite on a cargo-llvm-cov build, and the sonar job sends coverage/lcov.info to SonarQube Cloud. node-ci's sonar job likewise reads the LCOV report its test command writes (coverage-report)
- pubkit protect puts one ruleset, ruleset.json, on the default branch of every repository protected.json lists (no deletion or force push, pull requests only, each repository's required checks, no bypass), creating or updating it through gh; both files ship in the wheel, so an installed pubkit protects the repositories its release lists from any directory, and --config reads another list. --check reports how each differs and changes nothing; make protect runs it from a checkout. pubkit new prints the protected.json line instead of a gh api command

### Fixed
- Rewrites four regular expressions that backtracked super-linearly on long input (the tool version, cargo vet's crate lines, impl lines and the standard's [checked] tags)

### Security
- pubkit refuses a --body, --report or --changed-files path outside the working directory and the temporary directories, a pubrel row's text that starts with '-', and a crate name that is not one, so no argument can reach another file or pass another program an option
- Pins pytest 9.0.3, which fixes CVE-2025-71176, in the shared requirements

### Internal
- The nightly script uses [[ ]] for its tests

## 0.11.2 - 2026-10-20

Commit `9c91f331d80b`; release record `pub:sha2-256:gdaolbca5j6gqrlfah2l6corstkoilqsbsuyuxyy32lfqcuwxc3q`.

### Added
- node-ci.yml, a reusable workflow for a Node package: npm ci without install scripts, npm test, optional browser tests (npx --no-install), pubkit sync --check, and the sonar and passed jobs; pubkit init --kind=utility seeds it where a package.json has no pyproject.toml beside it

### Security
- Every action pubkit's workflows use is pinned to a full commit hash, with its version in a comment, so a moved tag cannot change what runs

## 0.9.0 - 2026-10-13

## 0.6.0 - 2026-10-12

Commit `6cbd57f0e56c`; release record `pub:sha2-256:sg2wlhf72m4ogerlpr4uaplmw5blrg4vjllercahs5wlyutbvela`.

### Changed
- rust-ci.yml runs every make target the Rust crate standard requires: a plan job asks `pubkit required` for each job's targets. The gates and functional inputs now only add targets, the msrv and fuzz inputs are ignored, cross runs on i686 and s390x by default, and a new audit job runs make deny and make vet
- `pubkit sync --check` in a Rust repository now also runs `pubkit conform`, so it fails where the repository does not conform and declares no exception

### Added
- Stable rule IDs on every [checked] rule of the Rust crate standard, and standard.json generated from them and shipped in the package
- `pubkit required` lists the make targets each rust-ci.yml job must run in a repository, from standard.json
- `pubkit doc-coverage` writes and checks each published library's TESTING.md, moved here from publet's tools/doc-coverage.py
- pubkit.mk provides every target the standard names: doc-coverage, doc-coverage-check, vectors, vectors-check, publish-check, msrv, fuzz-smoke, deny, vet and required, with PUBLISHED_CRATES, VECTORS_GENERATE, VECTORS_DIRS, FUZZ_TARGETS and MSRV
- `pubkit conform` checks the standard's required files and settings (_documentation, lints, testdata/, fuzz/, deny.toml and supply-chain baselines, SECURITY.md) and that every workflow pins the pubkit the lock pins
- Dated exceptions in pubkit.json: an excepted rule's checks and make targets are skipped and listed as open, and an expired or unknown exception fails

## 0.4.0 - 2026-10-09

Commit `3dba53f0be11`; release record `pub:sha2-256:aqodzi6uq6gytgvywhr3xiznk24ezkdfpqwx2avqtw5wegs2lqla`.

### Changed
- pubkit is licensed under Apache-2.0, as publet is, instead of MIT.
- The Rust crate standard asks that Cargo include patterns be anchored with /, since a bare name matches at any depth.
- The Rust crate standard asks that `make publish-check` verify the package in its own target directory: sharing target/ leaves cargo reporting the crate up to date after its source changes.

### Added
- pubkit is a Claude Code plugin marketplace. Its rust-crate-quality plugin carries the Rust crate standard and an agent that audits a crate (library or command-line tool) against it, and writes or fixes the docs. Install it with `/plugin marketplace add schryer/pubkit`.

### Internal
- CI checks the built wheel carries every template, built from a clean copy of the source.
